# Revision Page — Guideline (System Documentation)

This page comes right after the title page and before the Table of Contents. It records who did what, and tracks the versions of the SD over time.

> The title page itself (project title, version, date, faculty, team name) and the Table of Contents are **not** part of these guidelines and are excluded.

The Revision Page has four parts.

## 1. Overview
Describe the content of the current version of the SD. State what this version covers compared to the previous one (e.g. which chapters or sections were added/updated).

## 2. Target Audience
State who the SD is written for (e.g. supervisor, examiner, developers, client/stakeholder).

## 3. Project Team Members
List the team members in a table, stating each person's role and the status of their assigned task for this SD version (complete, partially complete, incomplete). If a task was reassigned to another member, state that.

## 4. Version Control History
Track the versions of the document over time.

| Version | Primary Author(s) | Description of Version | Date Completed |
| :---- | :---- | :---- | :---- |
| 1.0 | Team leader (Full Name) | Completed Chapter X, Section… | dd/mm/yyyy |
| … |  |  |  |

**Notes on versioning (from the template):**
- The title page should show the latest version.
- First submission (Assignment 2) = version 1.0, second submission (Assignment 3) = 2.0, Alternative Assessment = 3.0. (Adjust to your own course/PSM milestones.)
- The primary author(s) is usually the team leader who compiles all material for submission.
