# Chapter 1: Introduction — Guideline (System Documentation)

The full System Documentation (SD) combines three documents: the SRS, the SDD and the STD. This chapter introduces the whole document.

> Remove any italic notes/instructions from your final submission.

## 1.1 Purpose
This subsection should:
1. State the purpose of the SD.
2. Specify the intended audience for the SD.

Start with something like: *"This SD describes…"*

## 1.2 Scope
This subsection should:
1. Identify the software product(s) to be produced by name (e.g. Host DBMS, Report Generator).
2. Explain what the software will, and (if necessary) will not, do.
3. Describe the application of the software, including relevant benefits, objectives and goals.
4. Be consistent with similar statements in higher-level specifications (e.g. the system requirements specification), if they exist.

Start with something like: *"The software product is…"*

## 1.3 Definitions, Acronyms and Abbreviations
Provide the definitions of all terms, acronyms and abbreviations used in the SD.

## 1.4 References
This subsection should:
1. Provide a complete list of all documents referenced elsewhere in the SD.
2. Identify each document by title, report number (if applicable), date and publishing organization.
3. Specify the sources from which the references can be obtained.

Use a standardized reference format.

## 1.5 Overview
This subsection should:
1. Describe what the rest of the SD contains.
2. Explain how the SD is organized.
