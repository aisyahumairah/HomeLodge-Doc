# Chapter 5: Discussion and Implementation Planning

## 5.1 Introduction

HomeLodge is developed to resolve the operational difficulties homestay operators face when managing multiple properties. Operators often start with a single unit, which is easily managed through phone calls and messaging applications. However, as they expand to several properties, coordinating bookings manually becomes unmanageable. This reliance on informal channels frequently leads to double-bookings, unstructured payment collection, and difficult physical key handovers. Hence, there is a need for a centralised platform that allows operators to track availability, process payments, and manage access systematically. Existing marketplace platforms are not entirely effective for independent operators because they impose mandatory commissions, restrict direct communication, and lack integrated QR code door access. Therefore, the proposed system provides a private booking management solution that gives operators full control and ensures guests experience a reliable reservation process.

Another problem that HomeLodge tackles is the lack of a formal audit trail and secure access control in manual operations. Handing over physical keys to guests or cleaning staff carries the risk of unauthorised duplication and leaves no record of who entered the property. Furthermore, calculating refunds and tracking booking extensions remains an exhausting manual process. The proposed system eases this process by generating time-limited QR codes for secure door access and automating the billing for extensions and refunds. Thus, this encourages operators to digitalise their workflows, reducing their administrative burden while ensuring that property access and financial records are securely maintained.

## 5.2 Achievements

In Projek Sarjana Muda (PSM) I, a number of milestones have been accomplished for the HomeLodge project. The initial accomplishment was identifying the problem background and the importance of the proposed system for operators managing multiple homestay units. Following this, the project's objectives and scopes were established to guide the development process. The current manual booking methods were then analysed to identify their operational weaknesses. A comparison between existing platforms—such as Airbnb, Booking.com, and MySyok—and HomeLodge was conducted to differentiate their features and highlight the specific advantages of a private, non-marketplace system.

Before selecting the development tools, various technologies were studied and their pros and cons evaluated. This included assessing backend frameworks, real-time communication protocols, and frontend libraries. Another major accomplishment was selecting a hybrid software development methodology, combining Waterfall and Agile, and describing its specific phases and events. In addition, the background study specified the hardware and software justifications, alongside the detailed input and output requirements for all system modules. Finally, the requirement analysis and design stage produced several critical diagrams—including use case diagrams, an entity-relationship diagram, and activity diagrams—to represent the control and flow of the system. The system design and its user interface wireframes were also completed to provide a clear preview of the final application.

## 5.3 Suggested Plan for Project Implementation (PSM 2)

The second phase of the project, PSM II, will shift focus entirely to system development, testing, and deployment. The implementation will begin with configuring the local development environment, ensuring the web server, database, and all necessary software dependencies are correctly set up. Once the environment is stable, backend development will commence using the Laravel framework. This stage involves building the database schema, creating the API endpoints, and writing the core logic for all eleven functional modules, including authentication, booking management, and the QR code door access system.

As the backend takes shape, frontend development will run concurrently. The previously designed wireframes will be built into functional web interfaces using HTML, CSS, and JavaScript. The integration phase will then connect these frontend views with the backend services, while also incorporating external components like the online payment gateway and the WebSocket-based real-time chat. After development is complete, the system will undergo rigorous testing. The team will run unit, integration, and user acceptance tests (UAT) to find and fix bugs, verifying that the platform meets the initial requirements. Finally, the web application will be deployed and hosted on a live server for final evaluation and practical use.

## 5.4 Conclusion

This chapter summarises the current problems that led to the creation of the proposed system. The main problems identified are the absence of a centralised platform for operators to manage multiple homestay units and their heavy reliance on informal, error-prone booking channels. This highlights the need to build HomeLodge to solve these administrative issues. The chapter also states the planning for the implementation and testing phases that will take place in PSM II. All of the activities planned to implement the system are explained, such as backend configuration and the frontend development process. In summary, this chapter concludes the documentation of this project for PSM I.
